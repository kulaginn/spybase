# Управление ИИ-активностью

Ответственный — Рязанцев Д. (тимлид). В проекте использовался ИИ-ассистент (Claude) как инструмент разработки.
Ниже — правила, по которым команда управляла его работой.

## Для чего применяли ИИ

| Задача | Как использовали | Кто отвечает за проверку |
|---|---|---|
| Каркас модулей и схемы БД | ИИ предлагает черновик по нашей архитектуре (документ «Архитектура SpyBase», ER-диаграмма) | автор модуля |
| Словарь ключевых слов классификатора на 5 языках | ИИ предлагает кандидатов, веса и состав утверждает аналитик | Исматов А. |
| Тест-кейсы | ИИ предлагает граничные случаи, итоговый набор сверяется с каталогом ошибок | Саргсян Л. |
| Интерфейс | черновик вёрстки, доработка вручную | Саргсян Л. |
| Документация | черновики README и описаний | автор раздела |

## Правила

1. **Задача ставится по нашим документам.** В запрос к ИИ передаются требования (FR), архитектурные решения и
   каталог ошибок, а не «сделай спай-сервис». Так результат совпадает с архитектурой, а не с фантазией модели.
2. **Человек отвечает за код.** Каждый фрагмент от ИИ автор читает, запускает и при необходимости переписывает.
   Автор коммита = ответственный за этот код.
3. **Никакого кода без проверок.** Всё, что предложил ИИ, проходит те же ruff, mypy, bandit и pytest в CI,
   что и написанное вручную (см. [STATIC_TESTING.md](STATIC_TESTING.md)). Пример: ошибку типов в `repository.py`
   в коде, написанном с ИИ, поймал mypy, а не ревью.
4. **Секреты и личные данные в ИИ не передаются:** ключи, пароли, реальные данные пользователей, ответы респондентов
   опроса с контактами.
5. **Демо-данные вымышленные:** рекламодатели и домены `.example` — чтобы не публиковать чужие реальные креативы.
6. **Архитектурные инварианты не отдаются на усмотрение ИИ:** в базу попадает только платная реклама;
   SQL только с параметрами; интерфейс работает с данными только через API.
7. **Прозрачность:** использование ИИ отмечается в описании pull request (что сгенерировано, что изменено руками).

## Что ИИ не делал

Архитектурные решения, выбор ниш и метрик, распределение ответственности, исследование пользователей и
интервью с медиабайерами выполняла команда. ИИ использовался как ускоритель написания кода и тестов под эти решения.
